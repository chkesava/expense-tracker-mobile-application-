# React Native & Expo Developer Handbook

Welcome to mobile app development! This handbook serves as a quick reference sheet for running, debugging, and building your Expo React Native application.

---

## 🚀 1. Local Development Commands

### Start the Expo Dev Server
Starts the bundler and shows the developer CLI menu.
```bash
npx expo start
```
* **Useful Flags:**
  * `npx expo start --clear` (Clear the bundler cache; use this if the app behaves weirdly or fails to load code changes).

### Run on Android (Development Build)
Compiles the native Android code and runs the application on a connected device or emulator.
```bash
npm run android
# Or:
npx expo run:android
```
> [!IMPORTANT]
> Use this instead of Expo Go if your app uses custom native modules (like Google Sign-In).

### Toggle Developer Menu (In-App)
* On Emulator: Press `d` in the terminal, or `Ctrl + M` (Windows) / `Cmd + M` (Mac) on the emulator screen.
* On Physical Device: Shake your device.
* Press `r` in the terminal to reload the JavaScript bundle.

## 📦 2. Managing Packages & Assets

### Install a Library
Always use `expo install` instead of `npm install` for Expo SDK modules, as it automatically selects the version compatible with your Expo SDK version.
```bash
npx expo install <package-name>
# Example:
npx expo install expo-secure-store
```

### Sync Native Configurations (Prebuild)
Generates or updates the `android` and `ios` folders based on your `app.json` config.
```bash
npx expo prebuild
```
* **Reset Native Folders:** If native code gets corrupted or you change native plugins, clean and regenerate the folders:
  ```bash
  npx expo prebuild --clean
  ```

## 🛠️ 3. Troubleshooting & Diagnostics

### Get Android SHA-1 & SHA-256 Fingerprints (Local Debug)
Use this command to retrieve the fingerprints of your local development environment to register in Firebase or Google Console:
```bash
keytool -list -v -keystore android/app/debug.keystore -alias androiddebugkey -storepass android
```

### Clean Android Build Cache
If the Android build fails due to cache issues, navigate to the `android` folder and run clean:
```bash
cd android
./gradlew clean
cd ..
```

### Common Errors & Solutions

#### ❌ Error: `RNGoogleSignin could not be found`
* **Why:** You started the app with Expo Go. Expo Go does not contain the native Google Sign-in code.
* **Fix:** Connect a device/emulator and run `npm run android` to compile the native code.

#### ❌ Error: `DEVELOPER_ERROR` during Google Sign-in
* **Why:** The SHA-1 fingerprint of the keystore signing your app is not registered in the Firebase/Google Cloud Console.
* **Fix:** Get your signing key's SHA-1 (using `keytool` or `eas credentials`) and add it to your Firebase Project Settings.

## 📦 4. Building the App (APK) via EAS Cloud

To build a standalone APK using Expo's cloud build servers:

### Step 1: Install EAS CLI & Log In
```bash
npm install -g eas-cli
eas login
```

### Step 2: Build the APK
We use the `preview` profile configured in `eas.json` to generate an APK (instead of an AAB for the Play Store):
```bash
eas build --platform android --profile preview
```
* Once the build completes, download the APK from the generated URL and install it on any Android device.

### Step 3: Enable Google Sign-In for the APK
Because the APK is signed with a new keystore generated by Expo, you must retrieve this new SHA-1 and add it to Firebase:
1. Get the EAS SHA-1 fingerprint:
   ```bash
   eas credentials
   ```
   *(Select Android → preview → copy the SHA-1)*
2. Add this fingerprint to your **Firebase Project Settings** -> **Android App**.
3. *No rebuild is needed!* Google Sign-in will start working automatically on devices with the APK installed.

## 💻 5. Building the APK Locally on Your Laptop

If you want to build the APK completely on your laptop (without Expo Cloud queues or limits):

### Option A: Build a Local Debug APK (Easiest)
This creates a self-contained debug app using your local `debug.keystore`. Once installed, it runs completely offline/standalone on your friends' devices (your laptop does **not** need to be running).

1. Generate the native project folders:
   ```bash
   npx expo prebuild
   ```
2. Navigate to the android folder and build:
   ```bash
   cd android
   ./gradlew assembleDebug
   ```
3. Locate the shareable APK at:
   `android/app/build/outputs/apk/debug/app-debug.apk`
4. Since we already added your local debug SHA-1 to Firebase, **Google Sign-In will work out-of-the-box** for anyone installing this APK.

### Option B: Build a Local Release APK (Production-Ready)
This creates an optimized production build signed with a release keystore.

1. **Generate a keystore file:** Run the following command (set a password you will remember):
   ```bash
   keytool -genkey -v -keystore my-release-key.keystore -alias my-key-alias -keyalg RSA -keysize 2048 -validity 10000
   ```
2. **Move the key:** Place `my-release-key.keystore` inside your `android/app/` folder.
3. **Configure Gradle:** In `android/gradle.properties`, add the credentials:
   ```properties
   MYAPP_RELEASE_STORE_FILE=my-release-key.keystore
   MYAPP_RELEASE_KEY_ALIAS=my-key-alias
   MYAPP_RELEASE_STORE_PASSWORD=your_password_here
   MYAPP_RELEASE_KEY_PASSWORD=your_password_here
   ```
4. **Compile the APK:**
   ```bash
   cd android
   ./gradlew assembleRelease
   ```
5. **Locate the APK at:**
   `android/app/build/outputs/apk/release/app-release.apk`
6. **Extract SHA-1 for Firebase:** You must extract the release SHA-1 signature and add it to Firebase Settings:
   ```bash
   keytool -list -v -keystore android/app/my-release-key.keystore -alias my-key-alias
   ```
   Copy the `SHA1` fingerprint from the output and save it under your Android App in the **Firebase Console (Project Settings)**.

## 📲 6. Pushing Updates Over-The-Air (OTA)

If you only changed Javascript/React Native code (no new native libraries or changes in `app.json`):
You can update your friends' installed apps without sending them a new APK.

Export the update package:
```bash
npx expo export
```
